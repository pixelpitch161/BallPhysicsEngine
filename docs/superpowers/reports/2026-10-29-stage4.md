## What works

- **bpe-vm** (new crate): compiles a node graph for one of four CPU roles (Rules, Bounce, Motion, Sound) into a program and runs it. Forty block kinds: values (number, vector, colour, random, time, gravity, maths, functions, clamp, compare, logic, choose, vector maths, reflect, colour mix and HSV, setting blocks), ball blocks (ball, ball is, pick a ball, count, counter value), eleven When triggers (start, hit, spawn, remove, enter, leave, beat, event, timer, counter reaches, at a time), six Ifs (chance, every nth, only once, cooldown, compare, is) and twelve Dos (grow, speed, kick, colour, remove, split, spawn, gravity, set a setting, fire an event, play a note, count). Every output passes a finite check, a depth guard and a budget of 256 actions per module per step stop runaway chains, and one evaluation reads each block once, so a value several blocks share costs nothing extra.
- **Rules module** (`rules.graph`, slot Rules on the scene, the arena and the balls): rules driven by the event log, with targets by name, tag or kind (Me, Anything, a thing, #tag, Any balls). Actions queue and apply at the start of the next step in the order queued; spawned balls cap at 4096 per thing. Rules on the scene run once with every thing in scope; a Rules module shared by several things keeps its own counters and timers per thing. A rule's Set keeps the setting's own type (a bool stays a bool).
- **Rules card** at Simple and More: one sentence per rule ("When hit › Grow"), its numbers inline (a wired parameter shows "from wire"), Remove per sentence (it takes the blocks that fed nothing else and keeps what another rule still reaches), an "Add rule" menu of ten recipes (Grow on hit, Shrink on hit, Speed up on hit, Split on hit, Colour on hit, Spawn every second, Remove when fast, Play a note on hit, Count hits, Pulse gravity) and "Open in nodes".
- **Nodes depth for Bounce, Motion and Sound**: each kind has a template graph bound to its settings. An unedited module runs on its native path; editing it in the panel marks it custom and it runs through the compiled graph; "Revert to template" (on the card and in the panel) goes back and keeps the slider values. A parity test proves the template path equals the native path on every stage 2 and stage 4 scene (event log hash and length, soundtrack samples). A custom module's setting blocks show as sliders on its Simple and More cards ("Show at Simple" from a block's menu picks which), and the native pickers it still has (the instrument) stay.
- **Node panel**: slides up under the preview (resizable), titled with the path ("Ball › Bounce"), the module's name and who shares it, "Compiles" or the compiler's message, and Close, Revert to template, Fit and Add block…. The proven editor is ported: pan and zoom, drag, box select, typed wires, palette search (double-click the canvas), duplicate, delete, undo through the scene's history. Blocks glow when a rule fires, counters show their value as a badge, and the target picker names the scene's things, tags and kinds (a removed thing reads "Missing thing"). Opening the panel never dirties the scene, and moving a block never rebuilds the playback.
- **Broken graphs**: a graph that does not compile shows a red badge on the tree row and the slot card (hover for the message), the message on the block in the panel, the thing falls back to the module its parent gives it, and the preview keeps playing.
- **Runtime**: an action queue, ball tints (rules colour a ball over its look; trails and particles follow), a Rules stage after each step, the scene seed in the world (random blocks and chance rules repeat from run to run and change with the seed), a fingerprint that hashes what a graph does rather than where its blocks sit, and checkpoints that carry the VM state, the queued actions and the tints, so seeking replays identically.
- **Scenes**: five in scenes/next with golden logs: Grow on hit (three balls that grow and count their hits), Split on hit (one ball splits in two on every hit, until there are 64), Colour by speed (a block of balls tinted by how hard each last hit), Bouncy when slow (a custom bounce graph that keeps more speed on slow hits) and Wind and melody (a custom motion graph with a swinging wind and a sound graph that walks up a scale).

## How to open Nodes

Select a thing, find the card (Bounce, Motion, Sound or Rules) and press Nodes next to Simple and More; the panel slides up under the preview. Close hides it; Nodes stays lit while it is open. Rules cards also have "Open in nodes" under the sentences.

## Merge with stage 3

Stage 3 (#34) landed on main while #35 was open, so main was merged into the branch (fifteen files conflicted, the runtime, the kit's bounce, motion and sound modules, the scenes and the inspector among them). What was reconciled:

- The bounce hook `respond_at` carries stage 3's `special` flag beside stage 4's context: the native path keeps the special bounciness and growth, and an edited bounce graph answers every hit, special or not (what it does against a special target is up to its blocks). Friction and ball–ball bounces read the settings from the new `BounceState`.
- `World::matches(me, thing, target)` keeps stage 4's form (Me reaches the Rules scope of `me`) and is what graphs use; the physics keeps stage 3's matcher (Me is the thing itself) for special targets and balls to hit. Things without a sim are still built into the world's kinds so a target can name them.
- The sound module walks its events once for both paths: "Plays when", "Only hits against" and "Shortest gap" pick the hits before a graph sees them, the graph's Play output overrides only the quietest-hit check, and a rule's Note event plays for the thing's own ball whatever "Plays when" says. The motion graph's native fallback includes stage 3's wind.
- Ball tints lay over stage 3's gradient and hue-shift colours (no copy of the tint column any more).
- The inspector: a Rules card on an inherited slot is read-only with "Change here"; a custom module's setting blocks sit above the unbound settings, which keep stage 3's override marks; the Nodes end of the depth switch is a request the app forwards to the panel. The Library window's switch has no Nodes end.
- `scenes::all()` now spans stages 2–4 (fifteen scenes) and the stage 4 scene files lost their stage4- prefix, as the other stages' files have none. The golden hashes of every scene are unchanged; the files were re-blessed for the new order only.
- With ball–ball hits in the log, "When hit" now fires for both balls of a pair: the kit hands a rules graph the hit from each ball's side (test `a_ball_to_ball_hit_fires_the_rule_for_both_balls`). Before, only the ball the log names first fired its rule.

## Gaps and rulings (for stages 6, 7 and 8, and the spec)

1. Look, Trail, Particles and Shader have no Nodes yet: their switch is off with the reason on hover. GPU graphs are a later stage.
2. `when.enter`, `when.leave` and `when.beat` compile but never fire: nothing emits Enter, Leave or Beat events until zones (stage 6) and beats (stage 7) land. The runtime's event kinds are there.
3. `do.note` carries loudness only; pitch on Note events comes with stage 7's music. A note plays the thing's sound module.
4. `when.hit` fires on ball–wall, ball–obstacle and (since the stage 3 merge) ball–ball hits; the "what" target accepts balls. Rules on folders: a folder has a Rules slot only if its kind lists one (stage 3's folder kind does not).
5. A custom module's setting blocks edit the shared module from any thing's card, without stage 3's per-thing override marks on those keys (the runtime still applies an override set another way); the unbound settings keep the marks.
6. A Rules module shared by several things runs once per linking thing with its own state (counters, once, timers); the card says so.
7. Bounce, Motion and Sound templates are bound to the module's settings on open; a setting block holds the value, the card's slider edits it, and the two never disagree. A module edited as nodes stores the whole graph in the scene file; an unedited one stores only its layout and is rebuilt from the kind's template on open.
8. For stage 8: the fingerprint ignores block positions, notes, names and the Simple set, so a randomizer may move or annotate blocks freely; `bpe_kit::recipes()` is the list behind "Add rule"; `resolve_scene` (not `bpe_core::resolve`) is the one that compiles graphs and reports broken ones.
9. Deferred from the review: dead rows count toward the 4096 cap and nothing compacts the ball table (a spawn-and-remove rule stops after 4096 lifetime spawns, far beyond a 20 s clip); the inspector rebuilds a custom card's template every frame (cheap today); a random block in a Motion graph repeats within a step's substeps; the tint column is cloned per thing per frame; a bounce template with a top speed above the runtime's ceiling scales twice where the native path scales once; the ledger's first six task lines quote the doctest count.
10. The node panel takes the Space, Delete and arrow keys while the pointer is over its canvas, so placing a block never toggles play.
