# Marks part 3 (rich paint) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Paint that feels like paint. Three new styles (Wet paint, Watercolour, Neon ink) beside Flat. Wet paint that dries, bleeds and drips on canvases and skins. Balls that pick up wet colour. Splats that can be any PNG or JPG picture.

**Architecture:**
- The simulation owns everything that changes the paint over time.
  - Grid cells remember when they were painted, who painted them and how thick the paint is.
  - At 30 Hz a tick evolves only tiles with wet paint: drips (runners) first, then pickup, then bleed. It logs Drip, Lift and Bleed marks.
- The graphics card replays the marks. Stamps go in log order, then lifts (a multiply pipeline in the same pass), then one bleed pass driven by the Bleed marks.
- Each canvas and skin gains a third texture, `body` (thickness). The styles are composite shaders that read the colour, the time painted and the thickness, so drying costs nothing per frame.
- Pictures are decoded once into a texture array (`PictureAtlas`). Marks name a picture by its slot in `World.pictures`.

**Tech Stack:** Rust workspace: bpe-runtime, bpe-kit, bpe-gfx (wgpu + WGSL), bpe-studio (egui 0.37), bpe-cli. Also the `image` 0.25 crate (already in Cargo.lock), added to bpe-gfx only.

**Spec:** `docs/superpowers/specs/2026-11-02-marks-part3-rich-paint-design.md`. Parts 1 and 2 (`2026-11-01-marks-layer-design.md`, `2026-11-02-marks-part2-skins-design.md`) still hold wherever this spec is silent. Read `CLAUDE.md` first. ## Global Constraints

- **Golden logs are byte-identical.**
  - Every existing line of `crates/bpe-kit/tests/golden.txt`, `golden-debug.txt`, `golden7.txt` and `golden7-debug.txt`, and the old engine's goldens, stays byte-identical.
  - Marks, tint, pickup (`World.picked`), pictures and skins never enter the log hash.
  - Only the four new demo lines may be added, at the end of `golden.txt` and `golden-debug.txt`.
  - Bless once in debug and once with `--release` (Task 14), then `git diff` the golden files: only added lines.
- **A scene without any Marks module is unchanged.**
  - Its `fingerprint`, its `World.looks` (empty), `World.skins` (empty), `World.picked` (empty) and `World.pictures` (empty) all stay as before.
  - Its pictures are byte-identical.
- **Existing marks scenes look the same.** With Style Flat and no bleed or drips, existing canvas and skin pictures stay as they are. All existing `canvas_pictures.rs` tests pass unchanged.
- **Deterministic, and seek equals straight play.**
  - The same run gives the same grids, runners, pickup tints and marks.
  - Seeking (playback on the processor and the GPU flow layers alike) gives the same result as playing straight through.
  - No `HashMap`/`HashSet` iteration in simulation code. Use `BTreeMap`/`Vec`. No wall clock, no thread scheduling, no `rand`.
- **The tick never touches physics.** It reads and writes only the canvas's or skin's own `CanvasState`, `World.picked` and the log's marks. It never writes bodies, walls, solids, events, poses or states of other things.
- **WGSL never names a field or variable `target`, `active` or `move`.** These are reserved or clash on some backends. Use `aim`, `live`, `shift` and the like.
- **Settings groups.**
  - Every module setting group is a section in `bpe_core::SECTION_ORDER`. "Paint trail" and "Splat" already are, and main's test `every_module_setting_has_a_known_section` enforces it.
  - Canvas thing groups stay "Area", "Look" and "Over time". The skin group stays "Paint skin".
- **Windows-friendly.**
  - Paths go through `std::path::Path`/`PathBuf`. Never build paths with string `+`.
  - Stored relative picture paths use `/` separators. Accept both `/` and `\` when reading.
  - Never `canonicalize` a path for storage, because Windows gives `\\?\` prefixes. File names may hold spaces and non-ASCII characters.
  - No Unix-only APIs.
- **Build environment.**
  - Every cargo command in this plan runs with `export CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0`.
  - GPU tests run with `BPE_REQUIRE_GPU=1` on lavapipe.
  - The existing `gpu()` helpers only print "no GPU adapter available, skipping" and return early. So after every GPU test run, check that this text does not appear in the output (see Task 0).
  - Every **new** GPU test helper written in this plan must `panic!("no GPU adapter")` when `BPE_REQUIRE_GPU` is set and no adapter is found.
- **Formatting and lints.** `cargo fmt` (max width 120) and `cargo clippy --workspace --all-targets -- -D warnings` must be clean before each commit. `cargo fmt` rewraps lines, so read a file again after formatting it before you make any scripted text replacement in it.
- **Commits.** One commit per task, with the message given in the task. End every commit message with the attribution lines the build thread is given.

```rust
// bpe-runtime/src/events.rs: MarkShape gains four variants, in this order, after Smear.
pub enum MarkShape { Stroke, Splat, Ring, Star, Crack, Burst, Dots, Smear, Drip, Picture, Lift, Bleed }

// bpe-gfx/src/canvas/stamp.rs: shape_number
// Stroke 0, Splat 1, Ring 2, Star 3, Crack 4, Burst 5, Dots 6, Smear 7, Drip 8, Picture 9, Lift 10, Bleed 11

// Ink each mark adds to a cell's `amount` (grid) and, divided by 255, to the GPU `body` texture.
// Stroke 96, Smear 160, Splat/Ring/Star/Crack/Burst/Dots 200, Picture 96, Drip 40, Lift 0, Bleed 0.

// Variant bits by shape:
//   Stroke: bit0 (1) square tip, bit1 (2) CONTINUES, bit2 (4) CONTINUED          (part 2, unchanged)
//   Smear:  bit1 (2) CONTINUES, bit2 (4) CONTINUED                                (part 2, unchanged)
//   Splat:  bits0-2 layout, bits3-4 squash                                        (part 2, unchanged)
//   Drip:   value 8 = DRIP_JOINED: leave out the start disc and the half-plane behind the start
//   Picture: bits0-4 slot (0..=15 in the table, 31 = not in the table), bit5 (32) = Tinted
//   Lift, Bleed: 0

// Mark field meaning for the new shapes:
//   Drip:    from→to capsule, radius → radius_to; angle = previous piece's direction (when DRIP_JOINED).
//            A drop is a Drip with from == to, variant 0.
//   Picture: from == to = centre; radius = half the square's side; angle = turn.
//   Lift:    from == to = centre; radius = disc radius; radius_to = share removed (0..1).
//   Bleed:   from = rect min corner, to = rect max corner (canvas pixels, from the canvas middle);
//            radius = dry time in seconds; radius_to = the Bleed setting (0..1).
//   colour / colour_to: the paint colour for Drip and Picture; [0.0; 4] for Lift and Bleed.
//   within: [1.0, 1.0] for all four.

// bpe-kit/src/things/canvas/grid.rs
pub const DRIP_JOINED: u8 = 8;
pub const TICK_HZ: u32 = 30;
pub fn tick_every(steps_per_second: u32) -> u64 { (steps_per_second / TICK_HZ).max(1) as u64 }
pub fn painter(thing: ThingId, item: u32) -> u8 { ((thing.0 as u64 * 31 + item as u64) % 255) as u8 + 1 }
```

```rust
// bpe-runtime/src/picked.rs
/// Paint a ball has picked up: a colour laid over its own as strongly as `amount` says, fading
/// back over `fade` seconds from `step`.
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Picked {
    /// Linear light.
    pub rgb: [f32; 3],
    /// How strongly it shows at `step`, 0..1.
    pub amount: f32,
    /// The world step it was last mixed at.
    pub step: u64,
    /// Seconds it takes to fade from 1 to 0; 0 never fades.
    pub fade: f32,
}

impl Picked {
    /// How strongly it shows at world step `now`: amount − (seconds since step) / fade, floored at 0.
    /// `fade <= 0` (or not finite) never fades. `now < step` counts as no time passed.
    pub fn shown(&self, now: u64, steps_per_second: u32) -> f32;

    /// Mixes `colour` (linear) in by `share` (0..1) at step `now`, fading over `fade`.
    /// With A = self.shown(now, sps) and s = share.clamp(0, 1):
    ///   A' = 1 − (1 − A)(1 − s)
    ///   rgb' = (rgb·A·(1 − s) + colour·s) / A'   (when A' > 0; else rgb' = colour)
    ///   amount = A', step = now, fade = fade.
    pub fn mix(&mut self, colour: [f32; 3], share: f32, now: u64, steps_per_second: u32, fade: f32);
}

/// `c` (linear, straight alpha) with ball `i` of `thing`'s picked-up paint over it:
/// rgb = lerp(c.rgb, picked.rgb, shown). Alpha unchanged. No entry, or shown 0: `c` unchanged.
pub fn with_picked(world: &World, thing: ThingId, i: usize, c: [f32; 4]) -> [f32; 4];
```

     - A cell in two grown tiles is worked out twice from `before`, giving the same answer. That is fine.

     - `step = world.step`, `target`, colour `[0.0; 4]`, `within [1,1]`, variant 0, angle 0.

**Files:** Modify `crates/bpe-kit/src/things/canvas/evolve.rs` and `skin.rs` (make `nearest` `pub(crate)`).

- **Starting on a skin.** The same as on a canvas (gravity in the thing's own frame), plus:

  - `g = gravity.normalize()` (no move when the length is ≤ 1e-3), and `line = &outline[on.line]`. If the line no longer exists, drop the runner.
  - `pull0 = g·u(seg)` and `dist = (30 + 150 × load) × max(|pull0|, 0.25) / per_second`.
  - Then `walk`:
    - looped means `line.len() > 2 && line[0] == line[last]`, and `segs = line.len() − 1`.
    - loop:
      - `d = line[seg+1] − line[seg]`. If `|d| < 1e-6`, step to the next segment in `dir`, or the first time, stop and treat it as flat.
