# Shape thing, part 1: the shape itself (plan)

Spec: `docs/superpowers/specs/2026-11-04-shape-thing-design.md` (read it first; it is the source of truth for every
behaviour named here). Mockups: https://claude.ai/artifact/BbFQLkEkiCmGJcd4gBeP7b.

Part 1 delivers: the `shape` thing replacing `arena`, its Body settings and `Value::Path`, moulding and curves in
the preview, two-sided and solid collision, plain white GPU drawing, the inspector's layout A with only the Body
layer, and the Arena removed. Part 2 (paint layers) is out of scope; do not add Colour and gradient, Outline, Glow,
Blend or Shader layers for shapes here.

Model: every step on Opus at high effort. One Opus review at the end (task 10), then the PR. No demo renders or
screenshots unless the owner asks.

## Ground rules

- Branch from `main`. Run `cargo test --workspace` in the background (several minutes). Use `CARGO_INCREMENTAL=0`.
- TDD per task: write the failing test, see it fail, implement, see it pass.
- Goldens: every line must stay the same **except `Ball pit`** (its capsule becomes a rectangle). Re-bless with
  `BLESS_GOLDEN=1` once in debug and once with `--release`, then `git diff crates/bpe-kit/tests/golden*.txt` must
  show only the `Ball pit` line changed in each file. Anything else moving is a bug in the "exact forms" of task 3.
- No other editor file may make up a colour (the style test); use `style::` tokens and `style::colour_of`.
- `cargo fmt` (width 120) rewraps lines; check old text exists before scripted replacements.
- Keep the old `ShapeInstance` pipeline in `bpe-gfx` (other code and gfx tests use it); only its `Outline::Rounded`
  arm goes.

## Task 1: `ShapePath` value and geometry (`bpe-core`)

Files: new `crates/bpe-core/src/shape_path.rs`; `value.rs`; `settings.rs`; `save.rs` (`Scene::FORMAT` 6 → 7,
wherever it is defined); `lib.rs` (pub use).

1. `ShapePath { points: Vec<[f32; 2]>, bends: Vec<Option<[[f32; 2]; 2]>> }`, derive
   `Clone, Debug, Default, PartialEq, Serialize, Deserialize`. Default (empty) means "no moulded outline".
   `is_finite()`, `is_valid()` (empty, or ≥3 points with `bends.len() == points.len()`, all finite).
2. `Value::Path(ShapePath)` and `ValueType::Path` ("never keyframed"). `accepts`: `is_valid()`.
   `impl SettingValue for ShapePath`. Then `grep -rn "Value::Points" crates` and add a `Value::Path` arm beside every
   match on `Points` (animation never interpolates it; `settings.rs:364`-style "is set" = non-empty; the studio's
   `widgets.rs` words: "Even" for empty, else e.g. "7 points, 1 curve" via `ShapePath::words()`).
3. Geometry, all in shape units, `glam::Vec2` in/out where handy:
   - `ShapePath::even(sides: u32) -> ShapePath`: corner k at angle `-FRAC_PI_2 + k·TAU/n`, all straight.
   - `ShapePath::circle() -> ShapePath`: 8 corners from the top, each side a cubic with tangent handles of length
     `4.0/3.0 * (TAU / 32.0).tan()`.
   - `side_count()`, `curve_count()`, `words()`.
   - `side_point(side, t) -> Vec2` (line lerp or cubic), `nearest_on_side(side, q) -> (t, Vec2, dist)` for lines
     exactly, for curves by sampling 32 t then 8 rounds of ternary refinement around the best.
   - `nearest_side(q) -> Option<(usize, f32, f32)>` (side, t, distance).
   - `flatten(per_curve: usize) -> Vec<Vec2>`: corners and, for a curved side, `per_curve - 1` inner points at equal
     t. The sim and the drawing both call it with `FLATTEN = 16` (a pub const).
   - Edits returning `bool` (changed): `add_point(side, t)` (lines: insert the point; curves: de Casteljau split so
     both halves trace the same curve); `delete_point(i)` (refuse at 3; rule from the spec); `create_curve(side)`
     (handles at 1/3 and 2/3 pushed away from the middle by `0.25 × side length`; "away from the middle" = the side
     of the line not containing the origin, or the left normal when the origin is on the line); `straighten(side)`;
     `move_point(i, to)`, `move_side(side, by)` (both corners; a curved side's handles move with it, and the handles
     of the neighbouring sides that touch the moved corners do not move); `move_bend(side, which, to)`.
   - `mirror_partner_point(i) -> Option<usize>`: the other point nearest `(−x, y)` of point i, `None` when point i is
     on the line (`|x| < 0.005`). `mirror_partner_bend(side, which) -> Option<(usize, usize)>` likewise over handles.
   - `is_axis_rectangle() -> Option<Vec2>` (half size): 4 straight sides, corners `(±a, ±b)` within 1e-6 relative.
4. Tests (in `shape_path.rs`): `even(6)` corners equal the Arena polygon's `Outline::Ring { sides: 6 }` corners —
   do this one in `bpe-runtime` tests instead if `bpe-core` can't see `Outline` (it can't: put it in task 2's tests);
   `circle()` flattened stays within 1e-4 of the unit circle; `add_point` on a curve keeps 64 sampled points of the
   outline within 1e-4; `delete_point` refuses at 3 and keeps outer handles; `create_curve` bulges away from the
   middle; `move_side` moves both corners; mirror partners on a symmetric hexagon; serde round trip of a scene holding
   a `Value::Path`; an invalid path (2 points, NaN) is refused by `accepts`; loading a format-6 file reports
   `OldEditor`.

## Task 2: two-sided walls (`bpe-runtime/src/walls.rs`, `world.rs`, `testing.rs`)

1. `Outline`: drop `Copy` (keep `Clone, Debug, PartialEq`); remove `Rounded` and `rounded_distance`; add
   `Path { center: Vec2, angle: f32, scale: f32, points: Arc<[Vec2]>, thickness: f32 }` (points = flattened, shape
   units). Every method (`point`, `center`, `thickness`, `angle`, `inside`) gets a `Path` arm: `point(u)` = where the
   ray from the centre at `angle + u` first leaves the polygon (largest crossing, so it reads well for drawing
   handles), `inside` = even-odd in shape units. Add `nearest(&self, p) -> (Vec2, Vec2)` (nearest point on the centre
   line and the unit normal pointing from it towards `p`) for every variant; Ring/Box polygons go through a stack array
   of corners (`[Vec2; 64]`, `sides ≤ 64`) and a shared segment routine.
2. `Wall`: add `solid: bool`; derive `Clone` not `Copy`. Fix every `Wall { .. }` literal (`testing.rs` TestWall,
   kit sims) and every by-value use (`match *outline` → `match outline`, `wall.outline` copies → refs).
3. Replace `keep_inside` with
   `pub fn keep_clear(position: &mut Vec2, previous: Vec2, velocity: Vec2, radius: f32, wall: &Wall) -> Option<Contact>`
   following the spec. Structure:
   - `let was_inside = !wall.solid && wall.outline.inside(previous);`
   - Hollow and `was_inside`: for `Ring`/`Box` call the **unchanged** body of today's `keep_inside` (move it into
     `fn keep_inside_exact`), so goldens stay. For `Path`: limit = `radius + thickness/2`; if `p` is outside or its
     distance to the centre line is under the limit, put it at `nearest + n_in·limit` (n_in points inside: the normal
     towards `p` if `p` is inside, else its opposite) and return `contact(.., outward = -n_in, ..)`.
   - Hollow and outside (and every solid wall): limit = `radius + thickness/2` (hollow) or `radius` (solid); `n_out`
     = towards `p` when `p` is outside, else opposite (for solid with `p` inside, push out of the nearest edge). If
     closer than the limit or on the wrong side: place at `nearest + n_out·limit`, `contact(.., outward = -n_out, ..)`.
   - Zero-length normal (centre exactly on the line): use the nearest segment's left normal, flipped to point to the
     side `previous` was on.
   Re-export `keep_clear` (and stop exporting `keep_inside`).
4. `world.rs` collide: pass `bodies.previous[i]`; iterate walls by reference (no copies).
5. Tests in `walls.rs`: the existing inside tests keep passing on Ring/Box unchanged; even polygon corners from
   `ShapePath::even(n)` (scaled) equal `Outline::Ring { sides: n, angle: -FRAC_PI_2 … }` corners (pick the angle the
   kit sim will use, see task 3, and assert both agree); a ball outside a hollow ring bounces off its outside; a ball
   inside a hollow path stays inside; a solid box pushes an outside ball back out and a ball that starts inside out of
   the nearest edge; a 6 px ball at 6000 px/s does not cross a 2 px hollow band over 2 s (run through `World` with
   substeps); `nearest` agrees with brute force on random points for every variant.

## Task 3: the Shape thing (`bpe-kit`)

Files: new `crates/bpe-kit/src/things/shape/{mod.rs,sim.rs,draw.rs}`; delete `things/arena/`; `things/mod.rs`;
`lib.rs`; `starters.rs`; `modules/bounce/mod.rs`; `modules/look/mod.rs`; new `modules/look/shape.rs`;

1. `ShapeSettings` (`#[derive(Settings)]`) exactly as the spec's table: `start: ShapeStart { Polygon, Circle }`
   (default Circle), `sides: u32` (range 3..64, default 6, `when = "start=polygon"`), `size` (keyframe, simple),
   `fill: ShapeFill { Filled, Hollow }` (default Hollow), `thickness` (keyframe, `when = "fill=hollow"`),
   `path: ShapePath` (label "Corners", `when = "start=polygon"`), all `group = "Body"`; then `spin`, `shrink`,
   `min_size` ungrouped. `pub const BODY_HEADINGS: [&str; 1] = ["Body"];`. Test helpers (in `mod.rs`, not test-only
   so `scenes.rs` can use them): `ShapeSettings::circle(radius, thickness)`, `::polygon(sides, radius, thickness)`,
   `::rectangle(width, height, thickness)` (a 4-point path at `(±w/2, ±h/2)/s` with `size = s = hypot(w,h)/2`).

   slots Look/Bounce/Particles/Shader, default slots Look/Bounce. `affects_physics` on `ShapeSim`: true for every

   - Polygon, empty path → `Ring { radius: size, sides, angle: angle + FRAC_PI_2, thickness }` (the Arena's exact

   `ShapeState.outline()` applies turn/scale/riding to every variant (`Path` scales `scale`); `floor()` uses `size`

4. `ShapeDraw` stub here (task 5 fills it). Register `ShapeKind`, `ShapeSim`, `ShapeDraw`; remove the Arena's.
5. `look.shape` card: `ShapeLookKind` (`id "look.shape"`, name "Look", slot Look, fits `"shape"`) and one layer kind

   `ShapeSettings::circle(508.0, 3.0)` params (the old default). `scenes.rs`: `b.arena(|a| …)` → `b.shape(settings)`

## Task 4: the path pipeline (`bpe-gfx`)

Files: `frame.rs` (types + `cull`), new `shaders/paths.wgsl`, `lib.rs` (buffers, pipeline, draw calls),
`pictures.rs` or a new `paths_tests.rs`.

1. Types (`#[repr(C)] Pod`):
   `PathInstance { a: [f32; 4] /* centre x, y, angle, scale */, b: [f32; 4] /* half thickness (0 = solid), kind (0 circle,
   1 points), first point, point count */, c: [f32; 4] /* thing code, bound radius (shape units), 0, 0 */,
   color: [f32; 4] }` and `Frame.paths: Vec<PathInstance>`, `Frame.path_points: Vec<[f32; 4]>` (xy used, vec4 for
   storage alignment).
2. `paths.wgsl`: instanced quad covering the bound (`bound·scale + half thickness + 2 px`) in world space through the
   same camera transform the shapes pipeline uses. Fragment: transform to shape units; circle: `d = |len(q) − 1|·scale`
   with inside = `len < 1`; points: loop over the instance's segments in the storage buffer for min distance and
   even-odd crossings. Coverage: solid → `smoothstep` over one screen pixel at the signed distance; hollow →
   `half thickness − d` over one pixel. Premultiplied output like the other pipelines; thing code written where the
   shapes pipeline writes it (object pass).
3. `lib.rs`: a storage `GrowableBuffer` for points (upload `[[0.0; 4]]` when empty, like `look_layers`) and a vertex
   buffer for instances; build the pipeline next to the shapes one; draw `f.paths` immediately after `f.shapes` in
   `draw_back`, in `draw_objects`, and wherever else `f.shapes` is drawn (grep `shapes` in `bpe-gfx/src/lib.rs` and
   follow every use, including blend layers and the camera overlay frame). `Frame::cull` keeps paths that touch the
   view.
4. Tests (GPU picture tests skip without an adapter like the others): a hollow and a solid path square and a hollow
   circle drawn white on black: pixel at the band's middle ≈ white, inside a hollow one ≈ black, inside a solid one ≈
   white, 3 px outside ≈ black, the edge pixel between; `cull` keeps a path whose bound touches the view.

## Task 7: moulding in the preview (`bpe-studio`)

Files: new `crates/bpe-studio/src/shape_handles.rs` (geometry, hit test, drags, menus, drawing); `preview.rs`

   `Radius(ThingId)` replace `Edge`. `Handle::thing()` covers them.
2. Shape frame for a drag: the shape's middle and angle from the playback world's pose and its `size` (drags start at

3. Hit test (before the old wall-edge test, which goes): for the selected shape, in order bend handles (10 px),
   corners (8 px), circle radius dot (8 px), sides (within `EDGE_GRAB` of `nearest_side`); then for any shape

## Edge cases to handle (all covered by tests above)

- Self-crossing outlines: even-odd everywhere (collision, drawing, hit test).
- A ball bigger than a hollow Ring/Box it starts inside: still pinned at the centre (old behaviour).
- A ball spawned inside a solid shape: pushed out of the nearest edge on the first step.
- Deleting down to 3 points is refused; Add point on a curve does not change the outline.
- Shift with no partner (asymmetric shape): only the dragged point moves.
- A shape riding something (`Attach::Ride`): moves and turns with it as the Arena did.
- Undo after a Sides change restores the moulded path.
