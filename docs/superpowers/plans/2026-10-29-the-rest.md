# Modular Ball Studio, Stage 7 (The Rest) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keyframes and pulses on any flagged setting with a timeline panel, Soft body things (jelly, rope, cloth) that can be dragged in the preview, Text things drawn as signed-distance captions, and music: a song under the mix with ducking, a beat grid with Beat events, time-warp beat sync, a Drum machine and a MIDI Melody sound module.

**Architecture:** Keyframe tracks and pulses live on `bpe_core::Scene` keyed by `Address`; an `Animation` built from a scene and its `Resolved` writes the values at any time straight into a copy of `Resolved`, so the runtime (per step), the renderer (per frame) and the mixer (per window of events) all animate without knowing the registry. Soft bodies and Text are ordinary thing kinds in `bpe-kit` with their own folders; the runtime grows two defaulted `ThingSim` hooks (`after_step` with the log, `settings_changed` for keyframes) and the renderer grows two instance lists (soft triangles, glyph quads). Music is a `bpe-kit` module (`music/`) that decodes and analyses songs through `bpe-music`, lays a beat grid that Scene defaults turns into Beat events, fits a `TimeWarp` that export and the editor play through, and mixes the song under the notes.

**Tech Stack:** Rust 2024 workspace, bpe-core/bpe-runtime/bpe-gfx/bpe-mix/bpe-kit/bpe-cli/bpe-studio (stages 1 and 2), bpe-music (kept crate: `decode` feature with symphonia, `analyze`, `midi`), fontdue 0.9, glam 0.34, wgpu 30, eframe/egui 0.37, egui_kittest 0.37 (dev), hound (dev, for a generated test song).

**Spec:** `docs/superpowers/specs/2026-10-29-modular-studio-design.md` (3.7, 3.8, 4.7, 5.5, 7 stage 7, 8). Stage 2 report: `/mnt/project-files/ballphysics/modular-revamp/stage2/REPORT.md`.

## Global Constraints

- Old crates stay untouched. `bpe-music` is depended on, not edited. `bpe-graph` untouched. The new editor stays `ball-studio-next.exe` beside the old one.
- Stages 3 to 6 run in parallel on main. Changes to shared files (`bpe-core/src/scene.rs`, `bpe-runtime/src/{plugins,world}.rs`, `bpe-gfx/src/{frame,lib}.rs`, `bpe-mix/src/lib.rs`, `bpe-kit/src/lib.rs`, `bpe-studio/src/{app,inspector,widgets,preview}.rs`) are additive and as small as they can be: new fields at the end of structs, new defaulted trait methods, new functions, new match arms. New code goes in new files: `bpe-core/src/animation.rs`, `bpe-kit/src/things/{soft,text}/`, `bpe-kit/src/modules/{drums,melody}/`, `bpe-kit/src/music/`, `bpe-gfx/src/text/`, `bpe-studio/src/timeline/`, new golden/picture test files. Rebase on main before merging.
- Every map is a `BTreeMap`/`BTreeSet`. Iteration in `ThingId`, `ModuleId`, `Address` order. No rayon. The soft solver, the beat grid and the animation are deterministic: running twice, or seeking and playing on, gives the same event log hash.
- Stage 2 golden logs (`crates/bpe-kit/tests/golden*.txt`) and the five stage 2 scenes must not change: a scene with no tracks, no pulses, no song, `bpm` 0 and beat sync Off simulates exactly as before and logs no Beat events.
- `check_registry` rules hold: at most 6 Simple settings per kind; keyframe/pulse flags only on Number, Int, Vec2 and Color settings; defaults inside ranges.
- Plugin ids: things `"soft"`, `"text"`; modules `"sound.drums"`, `"sound.melody"`. Instrument `Drums` appended to `bpe_mix::Instrument`.
- Keys and pulses are evaluated on the simulation clock (`World::time()`, the `time` given to `build_frame`). With beat sync Off that is the video clock.
- Physics never pulses with hits (spec 5.5): the runtime evaluates pulses with `hits = 0`. The editor offers "Hits" only for settings that do not affect physics.
- Video output and the save format rules are unchanged (`Scene::FORMAT` stays 2; the new fields are `#[serde(default)]` so stage 2 files open).
- Code style follows the repo: `rustfmt.toml` (width 120), plain-English doc comments, every editor control `labelled_by` a label, `menu_button` pickers, painted icons (no glyphs outside the default fonts). Commit after every task with the attribution lines in effect.

## Review Focus

1. **A keyframed physics setting** (gravity, bounciness, arena radius) must change the simulation at the keyed time and restart the preview, while a keyed colour must not. Tests: `a_gravity_track_changes_the_world_at_its_time`, `a_look_track_leaves_the_fingerprint_alone` (Task 2).
2. **A soft body resting on the floor** must not buzz: a jelly ball lying still in the arena logs at most a handful of hits per second, never one per step. Test: `a_resting_jelly_does_not_buzz` (Task 4).
3. **A scene file pointing at a song that is missing** must still simulate, mix and export, silently without the song, and the editor must say so in the status line. Tests: `a_missing_song_mixes_silently_without_it` (Task 6), status text in the editor (Task 8).
4. **A text with every token and an empty text** must lay out without panicking and draw nothing for an empty string. Tests: `tokens_fill_from_the_run`, `empty_text_draws_nothing` (Task 5).
5. **Dragging a keyframe past its neighbour or off the end** must keep keys sorted and inside the video. Test: `moving_a_key_keeps_the_track_sorted_and_in_range` (Task 1).

### Task 1: Keyframes, pulses and the Animation in bpe-core

**Files:**
- Create: `crates/bpe-core/src/animation.rs`
- Modify: `crates/bpe-core/src/scene.rs` (Scene fields + Default), `crates/bpe-core/src/lib.rs` (module + re-exports)

**Interfaces:**
- Consumes: `Address`, `Owner`, `Value`, `Color::mix`, `Scene::def_at/value_at`, `Resolved`, `SlotLink`, `EditError::{UnknownSetting, WrongType}`.
- Produces (all `pub`, re-exported from `bpe_core`):
  - `pub const SAME_TIME: f64 = 0.004;`
  - `pub enum Ease { Smooth, Linear, EaseIn, EaseOut, Hold, Overshoot, Bounce, Curve { x1: f32, y1: f32, x2: f32, y2: f32 } }` with `pub const NAMED: [Ease; 7]`, `pub fn name(&self) -> &'static str` ("Smooth", "Linear", "Ease in", "Ease out", "Hold", "Overshoot", "Bounce", "Own curve"), `pub fn apply(&self, t: f32) -> f32` (Smooth = smoothstep; EaseIn = t²; EaseOut = 1-(1-t)²; Hold = 0 until t ≥ 1; Overshoot = back ease with 1.70158; Bounce = standard bounce-out; Curve = cubic Bézier (0,0)-(x1,y1)-(x2,y2)-(1,1) solved for x by 8 Newton steps, x1/x2 clamped 0..=1, y1/y2 clamped -0.5..=1.5).
  - `pub struct Key { pub time: f64, pub value: Value, pub ease: Ease }` — the ease shapes the change from this key to the next.
  - `pub struct Track { pub keys: Vec<Key>, pub range: Option<(f64, f64)> }` (keys sorted by time) with `value_at(&self, time) -> Option<Value>` (before the first key = first value, after the last = last value, between = `prev.value.lerp(&next.value, prev.ease.apply(t))`, numbers clamped to `range`), `key_near(&self, time, within) -> Option<usize>`, `set_key(&mut self, time, value) -> usize` (replaces a key within SAME_TIME, keeps its ease), `move_key(&mut self, index, time) -> usize` (re-sorts, returns the new index), `remove_key(&mut self, index)`.
  - `impl Value { pub fn lerp(&self, other: &Value, t: f32) -> Value }` — Number, Int (rounded), Vec2 linear; Color through `Color::mix`; any other pair returns `self` when t < 1 else `other`.
  - `pub enum PulseSource { Beat, Bass, Mid, Treble, Level, Hits }` with `NAMED: [PulseSource; 6]`, `name()` ("Beat", "Bass", "Mid", "Treble", "Level", "Hits").
  - `pub struct Pulse { pub source: PulseSource, pub amount: Value, pub decay: f32, pub range: Option<(f64, f64)> }` — `amount` is added at full strength (Number/Int/Vec2), or the colour mixed towards (Color); `decay` (default 0.25 s) is how long a beat's pulse takes to die away.
  - `pub struct Bands { pub rate: f32, pub bass: Vec<f32>, pub mid: Vec<f32>, pub treble: Vec<f32>, pub level: Vec<f32> }` with `at(&self, time) -> [f32; 4]` (linear between frames, 0 outside).
  - `pub struct PulseInputs { pub beats: Vec<f64>, pub bands: Option<Bands> }`.
  - `pub struct Inputs<'a> { pub pulse: Option<&'a PulseInputs>, pub hits: f32 }` with `Inputs::NONE`.
  - `pub fn pulse_strength(pulse: &Pulse, time: f64, inputs: &Inputs) -> f32`: Beat → `exp(-(time - last_beat) / decay)` for the latest beat ≤ time (0 with none); Bass/Mid/Treble/Level → the band at `time` (0 without bands); Hits → `inputs.hits`. Clamped 0..=1.
  - `impl Scene`: `set_key(&mut self, reg, a: &Address, time: f64, value: Value) -> Result<usize, EditError>` (UnknownSetting when `def_at` is None or the def lacks the keyframe flag; WrongType when `def.ty` doesn't accept `value`; fills `Track.range` from the def; time clamped ≥ 0), `remove_key(&mut self, a, index) -> bool` (drops an emptied track), `move_key(&mut self, a, index, time) -> Option<usize>`, `set_ease(&mut self, a, index, ease) -> bool`, `set_pulse(&mut self, reg, a, source, amount: Value, decay: f32) -> Result<(), EditError>` (needs the pulse flag), `remove_pulse(&mut self, a) -> bool`, `value_at_time(&self, reg, a, time) -> Option<Value>` (the track's value, else `value_at`), `keyed(&self, a) -> bool`.
  - `pub struct Animation` (Clone) with `new(scene: &Scene, resolved: &Resolved) -> Animation`, `is_empty(&self) -> bool`, `destinations(&self) -> impl Iterator<Item = (ThingId, Option<SlotId>, &str)>` (deduplicated, sorted), `apply(&self, resolved: &mut Resolved, time: f64, inputs: &Inputs)` (keyed value first, then the pulse added on top, numbers clamped to the range), `retain(&mut self, keep: impl FnMut(ThingId, Option<SlotId>, &str) -> bool)`.
  - Destination rules: `Owner::Thing(t), slot None` → `(t, None)` when `t` is resolved. `Owner::Thing(t), slot Some(s)` → `(t, Some(s))` plus every resolved thing `x` whose `slots[s].from == t`. `Owner::Module(m)` → every resolved thing `x` whose `slots[module.slot].module == m`, except when the thing `slots[s].from` links `m` with an override for the key.
