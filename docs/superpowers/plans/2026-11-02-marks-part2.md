# Marks part 2 (skin paint, better splats, clean trails) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Splats paint the wall or obstacle they hit (its own "skin", Print or Spread), splat shapes look like paint, and trails are clean continuous ribbons.

**Architecture:** A skin is part 1's canvas machinery owned by a wall/obstacle instead of a tree entry: a `CanvasState` in `World.skins`, posed with its thing, marks logged with `MarkTarget::Skin`, replayed on the GPU as a `Layer::Canvas` and composited through a shape mask. Trails become ribbons: the sim logs smoothed, joined pieces carrying start/end radius and colour; the stamp shader draws joints once.

**Tech Stack:** Rust workspace (bpe-core, bpe-runtime, bpe-kit, bpe-gfx wgpu/WGSL, bpe-studio egui 0.37).

**Spec:** `docs/superpowers/specs/2026-11-02-marks-part2-skins-design.md` (part 1 spec `2026-11-01-marks-layer-design.md` still holds where this one is silent). Read `CLAUDE.md` first.

## Global Constraints

- Golden logs of every existing scene stay byte-identical; marks and skins never enter the log hash. Only new demo lines may be added (bless debug and `--release`).
- A scene without any Marks module keeps its fingerprint, `World.looks` empty and no skins.
- Same run gives the same marks and grids, and seeking back gives the same picture as playing straight through.
- Skins exist only for arenas and obstacles with `skin_on` when some brush has Splat on with Lands on Thing hit or Both.
- Skin marks are in the owning thing's local frame (its pose each step).
- Paint skin settings: `skin_on` true, `skin_width` 0..3 default 1.0, `skin_fade` seconds (0 = never), `skin_opacity` 0..1 default 1 (keyframe). Label group "Paint skin".
- Splat: `splat_onto` Thing hit / Canvases / Both (default Thing hit), `splat_skin` Print / Spread (default Print). Print centre pushed `0.3 × radius` into the surface. Spread length `2 × splat_size × (1 + splat_by_speed × min(speed/1000, 2))`, pieces ≤ 8 px, tapering to 0 at both ends; circles and rings use 64 outline segments.
- Trails: `paint_taper` 0..1 default 0.3 (first and last `taper × 40 px`), `paint_smooth` 0..1 default 0.5; Catmull-Rom pieces ≤ 6 px; no smoothing across a hit.
- WGSL: never name a field `target`, `active` or `move`.
- Build with `export CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0`; GPU tests with `BPE_REQUIRE_GPU=1` (lavapipe).
- Every module setting group must be a section in `bpe_core::SECTION_ORDER` (main's test enforces it).

## Review Focus

- A spinning or moving obstacle: its skin paint must turn and move with it, never smear in world space. (Task 5 test `skin_marks_follow_a_spinning_bar`, Task 7 picture.)
- A growing/shrinking arena (wall `growth`): the skin must scale with the outline or at least never show paint off the line; the mask always comes from this frame's outline. (Task 7 test `skin_mask_follows_a_shrinking_ring`.)
- Hits right at a polygon corner or a box corner: Spread must turn the corner, not cut across it. (Task 6 test `spread_turns_a_box_corner`.)
- Many fast hits (a ring of 50 balls): skin memory and the per-step cost stay bounded. (Task 9 speed test.)
- A half-transparent paint colour: ribbon joints must not show darker beads. (Task 3 pixel test.)

### Task 3: Ribbons: smoothing, taper, speed smoothing, single joints

**Files:**
- Modify: `crates/bpe-kit/src/modules/marks/mod.rs` (settings `paint_taper`, `paint_smooth`), `crates/bpe-kit/src/things/canvas/sim.rs` (strokes), `shaders/canvas_stamp.wgsl` (joint).
- Test: `canvas/sim.rs` tests, `crates/bpe-kit/tests/canvas_pictures.rs`.

**Interfaces:**
- Consumes: Task 2's `radius_to`, `colour_to`.
- Produces: per-ball stroke state (in `CanvasState.last` or a new struct) holding the last 3 points, smoothed radius, the ribbon's length so far, and a "continues" flag; Stroke marks with `variant` bit 1 set meaning "continues the previous piece: leave out the start disc".

- [ ] **Step 1:** Tests (sim): `ribbon_pieces_join_exactly` (each piece's `from` equals the previous piece's `to`, bit-for-bit); `ribbon_pieces_are_short` (no piece longer than 6 px for a ball at 2000 px/s); `ribbon_bends_at_a_hit` (the piece ending at a bounce point and the next one starting there aren't smoothed through it: the bounce point is a logged joint); `taper_narrows_the_ends` (with taper 0.3, the first piece's radius < 0.2 × full, and radius reaches full by 12 px of length; the last piece before the ball stops painting ends at radius 0); `speed_width_is_smoothed` (WidthBy::Speed with smooth 0.5: a sudden speed jump changes the radius by less than half the jump in the first piece). GPU: `ribbon_joints_have_no_beads` (a half-transparent ribbon's alpha along its centreline varies by less than 0.05).
- [ ] **Step 2:** Run, see them fail.
- [ ] **Step 3:** Implement: hold one point back and emit the Catmull-Rom segment between the previous two points, split into ≤ 6 px pieces; treat a hit (bodies.hits changed) as a corner; exponential average of speed width with factor `1 - paint_smooth`; taper over the first and last `taper × 40 px`; emit the closing tapered piece when painting stops, the ball dies or the load runs out. The shader leaves out the start cap (half-plane before `from`) when the continues bit is set. Grid stamping uses the same pieces.
- [ ] **Step 4:** Run workspace tests, the picture tests, clippy. Golden unchanged.
- [ ] **Step 5:** Commit `feat(marks): trails as smooth tapered ribbons`.

### Task 4: Paint-like splat shape

**Files:** `crates/bpe-gfx/src/shaders/canvas_stamp.wgsl`, `crates/bpe-kit/src/things/canvas/sim.rs` (direction, squash), GPU tests in `crates/bpe-gfx` or `canvas_pictures.rs`.

**Interfaces:**
- Produces: Splat marks use `angle` = the ball's direction of travel (the incoming direction: the mover's current velocity reflected about the hit normal, `v - 2(v·n)n`; `-normal` when the mover has no body velocity), and `variant` = layout (low 3 bits) | squash level 0–3 (bits 3–4: 0 below 600 px/s, rising to 3 at 1800 px/s). Shared WGSL `splat_paint(q, r, variant) -> f32` reused by skins.

- [ ] **Step 1:** GPU tests: `splat_has_droplets` (more than one connected blob of coverage for every variant 0..7); `splat_droplets_lean_forward` (coverage centroid shifted along `angle` by > 0.1 r); `squashed_splat_is_flatter` (squash 3: extent across `angle`'s normal / extent along ≥ 1.4); `splat_edges_are_antialiased` (some texels with cover strictly between 0.1 and 0.9 on the edge).
- [ ] **Step 2:** Run, see them fail.
- [ ] **Step 3:** Implement: smooth-union (polynomial smin, k = 0.25 r) of 3–5 offset discs, 4–9 droplets at 0.9–1.6 r spread ±50° around `angle`, a streak capsule along `angle`; squash scales the blob frame. Keep Ring/Star/Crack/Burst/Dots.
- [ ] **Step 4:** Run tests + pictures + clippy.
- [ ] **Step 5:** Commit `feat(marks): splats that look like thrown paint`.
